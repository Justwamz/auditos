# Mobile Layout, Installable App and Firm-Logo Icon Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make every page comfortable on a phone, let people add AuditOS to their home screen, and show the firm's logo as the tab and home-screen icon.

**Architecture:** Below 52rem the side menu becomes a drawer opened by a "Menu" button in a slim top bar; shared CSS rules and a `TableScroll` wrapper keep tables, side panels and forms inside the screen, checked by e2e helpers that fail on horizontal overflow, small tap targets and small input text. A hand-written service worker in `public/sw.js` caches only `/offline`, the AuditOS icons and hashed `/_next/static/` files; navigations are network-only with the offline page as fallback. The API renders a square PNG from a firm's logo version (`GET /branding/icon/:id/:variant`, sharp, tenant-scoped, cached by logo id), and the web app points its favicon, Apple icon and a per-request manifest (`/site.webmanifest`) at it, falling back to static AuditOS icons.

**Tech Stack:** Next.js 15 App Router / React 19 (plain CSS in `apps/web/app/globals.css`), Fastify + Postgres RLS, `sharp` (new API dependency), Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-29-mobile-pwa-design.md` (binding; "Owner's decisions" and "Non-goals and anti-goals" are part of it).

## Global Constraints

- Widths that must be right: 375px and 390px (phone), 768px (tablet), 1280px (desktop). No horizontal page scroll at any of them; input, select and textarea text at least 16px; tap targets at least 44px tall and wide (inline text links in sentences and calendar event blocks excepted).
- Drawer layout applies at `max-width: 52rem` (today's breakpoint; 768px gets the drawer). Narrow-only reflows (stacked table rows, full-screen side panels) apply at `max-width: 40rem`. Desktop look at 1280px does not change.
- The ten-link menu cap (`lib/nav.ts`) still holds; the drawer shows exactly `navFor(role, isAdmin)`.
- Drawer: a dialog-like region labelled "Menu", visible focus ring, Escape closes, tapping outside closes, choosing a link closes, focus returns to the "Menu" button; `prefers-reduced-motion` means no slide animation.
- Manifest: name and short name AuditOS when signed out, `display: standalone`, `start_url: '/'`, icons 192, 512 and a maskable 512; linked with `crossorigin="use-credentials"`. Signed in: name = firm name, icons = the firm's square icon route when it has a logo.
- The service worker never caches or serves authenticated responses: no pages other than `/offline`, no `/api/*` (so no `/me`, logos or icons), no `/site.webmanifest`. `sw.js` is served from the site root with `Cache-Control: no-cache, no-store, must-revalidate`.
- Firm icon: logo centred on a white square with padding, any size; when the firm has no logo, or its logo cannot be read, the AuditOS icon is used. The sign-in page and signed-out visitors always get the AuditOS icon. Decode only after `checkLogo(bytes).ok` (which runs `pngDecodes` for PNGs); any failure falls back. Another firm's logo id returns 404.
- "Install AuditOS" button only when the browser offers installing, never on the sign-in page, dismissible ("Not now" is remembered on that device).
- No offline data, no offline editing, no push notifications. No change to what anyone may see or do. "Powered by AuditOS" stays; AuditOS stays on the sign-in page.
- Plain words in all user text (`apps/web/lib/plain.ts` `BANNED_WORDS`, mirrored in `e2e/helpers.ts` `BANNED`): never "session", "token", "API", "cache", "service worker", "manifest", "PWA" in anything a person reads. Shared primitives (`PageHead`, `SidePanel`, `SectionHead`, `Chips`, `Segmented`, `TabBar`, `RowMenu`) are fixed once rather than per page.
- Help stays true: tasks that change what a person sees update `packages/help/content` in the same task; `pnpm --filter @auditos/help test` must pass.
- Strict TypeScript (`noUncheckedIndexedAccess`). Restore `apps/web/tsconfig.tsbuildinfo` if a typecheck changes it. E2E keeps its isolated ports (web 3100, API 4110) and the private Postgres on 5433 (never 5432); run spec files one at a time. Never print secrets (database URLs, `.e2e-credentials.local.json`, environment values) in logs, tests or reports.
- New dependency: `sharp` in `apps/api` only (prebuilt binaries for Windows dev and Linux on Render). Report it to the owner in the final summary.

## Review Focus

- A person who signs out on a shared phone (or switches firm) and then opens the app offline sees the plain offline page, never the previous person's pages or data: nothing under `/api/` or any HTML other than `/offline` is ever in the cache (Task 4).
- After a new deploy, an installed copy does not keep running old files: `sw.js` is never HTTP-cached and caches from an older version name are deleted when the new worker takes over (Task 4).
- An extreme logo (a 2000x20 strip, a 20x2000 bar, a transparent PNG, a JPEG whose body is damaged but whose header passed the upload check) gives a square, unstretched icon on white or falls back to the AuditOS icon; it never errors (Task 5).
- A very long unbroken client name, email address or prospect note at 375px does not make the page wider than the screen (Task 3).
- Turning the phone or widening the window while the drawer is open leaves a normal desktop menu: no dialog role, page scroll not locked, links visible (Task 1).
